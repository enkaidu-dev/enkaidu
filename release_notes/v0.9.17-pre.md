
#### CHANGE

#### FEATURES

- The `spawn_agent` tool supports a `max_agent_depth: N` tool setting that can be used to control how deep sub-agents can spawn further sub-agents.
  - Default maximum depth is `2`
  - The maximum depth settings supports an inclusive range of 0 to 5.
- Allow the user to interrupt a session turn where the LLM is busy responding and the user cannot enter any input
  - The console UX supports user interrupt by handling `Ctrl-C` to stop as soon as possible and then clean up the turn so that you can continue if you want to.
  - The web UI supports a "Stop" button in the prompt bar to allow the user to interrupt during a turn when otherwise no user input is allowed.

#### EXPERIMENTAL

- Enkaidu supports a repetition tripwire that is used to monitor the responses from the LLM for situations where it degenerates into highly repetitive endless responses. This helps catch and interrupt turns that otherwise would run for a long time.
  - In the configuration file under `session:` you can configure
    - `repetition_tripwire: false` to disable the tripwire. It is enabled by default.
  - Why experimental? We might need more than just repetition detection, or maybe the default capture window and other parameters need to be tweaked.

#### EARLY ACCESS

- Added support for "Responses" protocol available via the following providers: `openai:responses`, `ollama:responses`, and `azure_foundry:responses`
  - When defining `llms` in the config file, use these when you want to use the responses protocol with those endpoints
  - The existing providers continue to be available via the "Chat Completions" protocol.

#### IMPROVEMENTS

- The `shell_command` tool truncates standard output and error content that exceeds 16K for each. If truncated, each indicates with a `truncated: true` property.
- The `shell_command` tool supports optional `save_as_file_path_prefix` and `overwrite` parameters that the calling model can use to save standard output and error content to temporary file.
- The `search_file_tool` enforces the required `files` parameter, limits `max_files` to no more than 10000, and reports an error when the search response total size exceeds 32K.
- The `find_files` tool limits `max` to no more than 10000 and reports an error when the files response total size exceeds 32K.
- In CLI mode, tool calls are shown with args as a table when not using quiet mode, making it easier to see all the parameters.
