
#### CHANGE

- The `Web` tools support host policies to control the servers / hosts that they can be used to access, with a change to the allow/deny lists behaviour as of this release.
  - Each of `http_get_web_page_as_markdown` and `http_get_web_page` support the following tool settings:
    - `allowed_hosts:` an array of host names that are always allowed, empty means none always allowed (default)
    - `denied_hosts:` an array of host names to always refuse to connect to, empty means none always denied (default)
    - `allow_private_hosts:` can be set to `true` allow access to private/local hosts, default is `false`
- The `exclude_past_reasoning` property, set via `session` or `llm:... model:...` settings, supports two values types:
  - If `true`, as before, all reasoning from past turns is excluded.
  - If a positive number of turns, then only reasoning from prior turns is excluded.
    - This allows you to preserve recent reasoning, only excluding from older turns.
    - A turn starts with a user input, and includes all tool calls and responses until next user input.
- Promote `/session pop_and_transform` out of experimental status.
- Normalize `/think` command to work like other slash commands
  - `/think current` returns th current think / reasoning effort level
  - `/think set LEVEL` changes the think / reasoning effort level

#### FEATURES

- The `Web` tools ask for user permission when a host is unknown (not allowed nor denied)
  - Each of `http_get_web_page_as_markdown` and `http_get_web_page` has their own allowed and denied lists
  - The permission options are to deny or allow once or always:
    - The terminal UI will present a four-letter choice: `a` to allow, `d` to deny, `A` to allow always, and `D` to deny always.
    - The web UI will present `Allow` and `Deny` buttons and a `[ ] Remember` checkbox allow or deny always.
- The web UI supports searching prompt history.
  - Use `Cmd-K` or `Ctrl-K` to open a search prompt and start typing to find matching past inputs.
  - `Cmd-R` or `Ctrl-R` also supported for terminal users who already reach for those shortcuts.
- The Web UI supports a macro picker for searching and auto-completing an available macro.
  - In an empty prompt bar start typing `!` and the macro picker will appear.
  - Continue typing to narrow the selection
- Each session generates a unique UUID that Enkaidu sends to the protocol server in the `x-enkaidu-session-id` header.
  - Forked sessions, including sub-agent sessions, have their own unique IDs distinct from the parent sessions.
- Adding an experimental `/session x-squish` command that "squishes" the current session history by keeping the initial request and final response for each turn, dropping everything in between.
  - In effect this drops all tool calling and intermediate responses for every turn, significantly shrinking the session size while retaining all request outcomes and nothing more.

#### EXPERIMENTAL

- The appearance of terminal output can be configured using a stylesheet defined in a top-level "console" section.
  - `console:` top level section, available via `enkaidu.yml` only
    - `stylesheet`: define the diferent element types and their styles
      - `ELEMENTNAME:` one of many supported TUI elements
        - `fg:` Foreground color
        - `bg:` Background color (optional)
        - `format:` Array of one or more of `italic`, `bold`, `underline`, `strikethrough`, `double_underline`
  - Colour values can be one of the following:
    - Predefined ANSI colours: `black`, `red`, `green`, `yellow`, `blue`, `magenta`, `cyan`, `light_gray`, `dark_gray`, `light_red`, `light_green`, `light_yellow`, `light_blue`, `light_magenta`, `light_cyan`, `white`
    - Integer value of ANSI 256-colour palette index (e.g. `124`)
    - Array with R, G, B values (e.g. `[112, 234, 43]`) if your terminal supports 24-bit colours.
  - Example:
    ```yml
    console:
      style_sheet:
        query_prefix_by_user:
          fg: yellow
          bg: darkgray
          format: [italic]
    ```
