
#### CHANGE

* The `auto_load:` section in the configuration file is **deprecated**.
  - The section's properties `mcp_servers`, `toolsets`, and `system_prompt_name` are available in the `session` section.
  - When specified there, the now deprecated `auto_load` section, if present in the config file, will be ignored.
  - _Why?_ As Enkaidu improves its multi-session and sub-agent supports, keeping the session-related configuration together allows us to better define what different sessions can and cannot do.

#### FEATURES

* As of the last release Cordon blocks environment variables unless they have been curated by the system and workspace options. Enkaidu now allows you to define and pass environment variables through into the Cordon. For example:
  ```yaml
  cordon:
    policy:
      allow_env:
        BOO: HOO
        EJSON_KEYDIR: $EJSON_KEYDIR`
  ```
  - As usual for other values in the configuration, you can specify your existing environment variables as values to pass through ones that Cordon would block otherwise.

#### EXPERIMENTAL

* The experimental `/session x-squish` command that "squishes" the current session history by keeping the initial request and final response for each turn now supports an optional parameter to specify how many past turns to exclude when squishing.
  - `/session x-squish exclude_past_turns=N` where `N` is the number of past (recent) turns to _not_ squish.
  - Default is `exclude_past_turns=0` which squishes all turns.
