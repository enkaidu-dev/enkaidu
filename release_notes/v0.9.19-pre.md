
#### CHANGE

* The `auto_load:` section in the configuration file is **deprecated**.
  - The section's properties `mcp_servers`, `toolsets`, and `system_prompt_name` are available in the `session` section.
  - When specified there, the now deprecated `auto_load` section, if present in the config file, will be ignored.
  - _Why?_ As Enkaidu improves its multi-session and sub-agent supports, keeping the session-related configuration together allows us to better define what different sessions can and cannot do.
* All the tool names have been simplified. E.g. `http_get_web_page_as_markdown` is now `fetch_markdown`, and `str_replace_lines_in_text_file` is now `replace_lines`.
  - However Enkaidu continues to supports the old names when tools are referenced by name, when selecting tools, configuring tools via tool settings, etc.
  - When an old name is used, Enkaidu will warn _once_ and only once for that session.
  - _Why?_ Simpler tool names are shorter and easier to understand both for humans and for AI models choosing tools from tool descriptions.
* The `/toolset compat` subcommand has been added to see a table mapping the deprecated tool names to the new names.
* The use of environment variables to configure the `shell_command` is **deprecated**.
  - Support for `ENKAIDU_ALLOWED_EXECUTABLES`, `ENKAIDU_APPROVED_EXECUTABLES` and `ENKAIDU_RESTRICTED_TERMS` will be removed in an upcoming release.
  - _Why?_ The configuration file supports arrays without which command _phrase_ prefix matching doesn't work.

#### FEATURES

* As of the last release Cordon blocks environment variables unless they have been curated by the system and workspace options. Enkaidu now allows you to define and pass environment variables through into the Cordon. For example:
  ```yaml
  cordon:
    policy:
      allow_env:
        BOO: HOO
        EJSON_KEYDIR: $EJSON_KEYDIR`
  ```
  - As usual for other values in the configuration, you can specify your existing environment variables as values to pass through ones that Cordon would block otherwise.

#### EXPERIMENTAL

* The experimental `/session x-squish` command that "squishes" the current session history by keeping the initial request and final response for each turn now supports an optional parameter to specify how many past turns to exclude when squishing.
  - `/session x-squish exclude_past_turns=N` where `N` is the number of past (recent) turns to _not_ squish.
  - Default is `exclude_past_turns=0` which squishes all turns.

#### IMPROVEMENTS

* The built-in tool definitions have been updated to make all the parameter names consistent and short as possible.
  - This does not affect any configuration or user input selection.
  - _Why?_ Shorter and consistent parameters keep the tool definitions shorter and clearer for the models.

#### FIXES

* Updated Cordon to improve Ruby and Python workspaces
  - Enabling Ruby now ensured `GEM_PATH` and `GEM_HOME` env variables are allowed through automatically if set, ensuring `chruby` environment changes stay in effect
  - Enabling Python virtual environment now ensures `PATH` is set properly to ensure the correct Python binary is used
