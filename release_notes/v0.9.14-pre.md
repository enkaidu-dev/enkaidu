
#### FEATURES

- The `shell_command` tool supports a list of commands for which network access is allowed when running in a cordon.
  - `tool_settings:`
    - `shell_command` sub-section for the specific tool
      - `network_allowed_commands:` is a list of allowed or approved commands that are run with network access enabled when cordon is enabled.
  - All other allowed commands are run without network access.
  - Allowed commands are prefix-matched, so you can allow a command and then allow network access for that command invoked with a subcommand. See example.
  - The cordon policy's `allow_network` setting must be `true` for this tool setting to work
  ```yml
  tool_settings:
    shell_command:
      allowed_commands: ["ops", "ruby"]
      # Only allow "ops test" to run with network, but other "ops" subcommands won't.
      network_allowed_commands: ["ops test"]
  ```
- The `Web` tools support host policies to control the servers that they can be used to access.
  - Each of `http_get_web_page_as_markdown` and `http_get_web_page` support the following tool settings:
    - `allowed_hosts:` an array of host names that are allowed, allow all if null (default)
    - `denied_hosts:` an array of host names to refuse to connect to, deny none if empty (default)
    - `allow_private_hosts:` can be set to `true` allow access to private/local hosts, default is `false`
  - Example
  ```yml
  tool_settings:
    http_get_web_page_as_markdown:
      denied_hosts: ["google.com"]
    http_get_web_page:
      allowed_hosts: ["google.com"]
  ```

#### EXPERIMENTAL

- When running in sandbox mode (**experimental**) using `enkaidu --sandbox`, Enkaidu will not load config from the sandbox folder.
  - Instead it looks for config and profile in the parent folder, allowing the user to control the config and to ensure the model doesn't take control of the config.
  - This is not an issue today but in future I plan to allow re-using past sandboxes, sort of like sessions.

#### IMPROVEMENTS

- The `http_get_web_page_as_markdown` tool now parses incoming HTML properly when converting to Markdown. Additionally, resulting content is too big (>32K) it truncates the Markdown. The tool returns the URL and a `truncated: true | false` property in addition to the Markdown.
